## 二、CRITICAL（必须立即修复）

### C1. 导出取消仅改状态，不断 FFmpeg 进程
**文件**: `packages/editor-core/src/export/export-queue.ts:192`
`cancelExportTask()` 只将任务状态设为 `canceled`，**不杀死底层 ffmpeg 子进程**。取消后进程继续消耗 CPU/内存。多次取消累积孤立进程，最终耗尽系统资源。
**修复**: 取消时调用 `AbortController.abort()` 或 `proc.kill()`。

### C2. Headless 渲染器无取消机制
**文件**: `packages/editor-core/src/headless/headless-renderer.ts:64`
`executeFfmpegRender()` 内部创建 `ChildProcess` 但不暴露给调用方，无 `AbortSignal`。长时间渲染无法被中断。
**修复**: 接受 `AbortSignal` 参数，监听信号调用 `proc.kill('SIGTERM')`。

## 三、HIGH（优先修复）

### H1. Tauri Bridge 穿透（4 处）
直接 `import { invoke } from '@tauri-apps/api/core'`，绕过 `tauri-bridge.ts`：
- `hooks/useGpuDetect.ts:2`
- `hooks/useModelManager.ts:2-3`
- `hooks/useVideoGeneration.ts:2-3`
- `video-gen/video-gen-runner.ts:1-2`

均为 v4.60+ LTX-Video 功能引入。影响：无法 mock 测试、类型安全降低、违反 AGENTS.md 规则14。

### H2. 后台任务无限流
proxy / waveform / thumbnail 生成**无并发限制**（无 semaphore / throttle）。若按素材逐个 spawn ffmpeg 子进程，可能瞬间撑满系统资源。违反 AGENTS.md 规则24。

### H3. Rust 依赖 CVE 待确认
`cargo audit` 未执行。quick-xml CVE (RUSTSEC-2026-0194/0195) 状态未知。虽风险可控（plist 仅解析本地文件），但需在 CI 中确认。

### H4. CLI --concurrency 为空操作
`packages/cli/src/commands/render.ts:88` 接受 `--concurrency` 参数并存储，但 `executeFfmpegRender` 永远只启动一个进程。用户期望的并行渲染完全不生效。
