## 1. 死代码检测 (knip)

### 1.1 总览

运行 `npx knip` 检测到 **603 个未使用导出**。

### 1.2 主要分布

| 模块 | 未使用导出数 | 类型 | 说明 |
|------|-------------|------|------|
| `InspectorEditors.tsx` | ~80+ | 函数/常量 | 大量 re-export 但中间层未使用 |
| `CurveEditors.tsx` | ~50+ | 函数 | 曲线编辑器内部工具函数 |
| `ColorEditors.tsx` | ~20+ | 函数 | 色轮/曲线绘制工具 |
| `EffectEditors.tsx` | ~15+ | 组件字段 | 特效编辑器子组件 |
| `creator-dashboard/src/lib/utils.ts` | 2 | 工具函数 | formatRelativeTime, seededColor |
| `style-model-manager.ts` | 2 | 函数 | findMatchingCluster, createDefaultStorage |

### 1.3 分析

大部分死代码集中在 `InspectorEditors.tsx` — 该文件大量 re-export 子模块的导出，但自身不使用。这些导出被其他文件直接 import 子模块获取，导致中间层 re-export 成为"死代码"。

knip 的输出包含真死代码和架构噪音两部分：
- **真死代码** (~30%): 已不再使用的工具函数（如 `formatRelativeTime`）
- **架构噪音** (~70%): re-export 中间层，实际被使用但 knip 追踪路径不同

## 5. 模块职责

### 5.1 editor-core 目录结构

`packages/editor-core/src/` 包含 ~80+ 个模块目录/文件，职责明确：
- `timeline/` — 时间线核心算法
- `export/` — FFmpeg 导出规划
- `project/` — 项目文件与迁移
- `ai/` — AI 辅助功能
- `cache/` — 缓存系统
- `ui/` — UI 状态管理（主题、快捷键）

### 5.2 潜在混杂

- `editor-core/src/` 根目录有大量 `.ts` 文件（如 `ai-beat-snap.ts`, `ai-broll-suggestion.ts`），部分属于 AI 模块但未收入 `ai/` 子目录。
- 编译产物（`.js`, `.d.ts`, `.js.map`）与源文件混在同一目录。建议 `tsconfig.build.json` 配置独立的 `outDir`。

## 6. 代码重复

未进行深度 AST 级别重复检测。从文件命名模式观察：
- Inspector 组件中 `CurveEditors.tsx` 和 `ColorEditors.tsx` 有高度相似的 canvas 绘制工具函数（`drawCurveCanvas`, `eventToCurvePoint`, `findNearestCurvePoint` 等同时存在于两个文件）。
- 建议抽取公共 Canvas 工具到 `shared/` 模块。

## 7. 关键发现与建议

### HIGH

1. **603 个 knip 未使用导出** — 虽然大部分是 re-export 架构噪音，但存在约 180 个真正死代码需要清理。长期积累会增加维护负担。
   - 建议: 分批清理，优先处理 `creator-dashboard`, `style-model-manager` 等明确无引用的导出

### MEDIUM

2. **编译产物与源文件混合** — `editor-core/src/` 目录中 `.js`/`.d.ts`/`.js.map` 与 `.ts` 混放，不便于区分和维护。
   - 建议: 配置 `outDir: "dist"` 将编译产物输出到独立目录

3. **InspectorEditors.tsx 中间层 re-export** — 大量函数通过 InspectorEditors 转发但自身不使用，既造成 knip 噪音又增加不必要的依赖层级。
   - 建议: 使用者直接 import 子模块，废弃中间层 re-export

4. **MediaCard.tsx (1050行)** — UI + 状态 + 事件逻辑混杂。
   - 建议: 拆分为 `MediaCardView.tsx` + `useMediaCardState.ts`

### LOW

5. **`as any` 58 处** — 虽不算多，但部分集中在导出模块，可能隐藏类型错误。建议逐步用 `unknown` + 类型守卫替换。
